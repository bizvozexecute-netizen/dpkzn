## Железные ограничения (нарушение любого = провал задачи)

- **SEO переносится 1:1.** Все URL, title, description, H1, тексты услуг, SEO-тексты, FAQ, статьи блога, перелинковка — байт в байт как сейчас. Исключения ровно два (утверждены): description `/polirovka-stekol` — «стёкл»→«стёкол»; description `/polirovka-far` — цену привести к прайсу страницы. Прежде чем менять шаблон — выгрузи текущий контент каждой страницы в данные (миграционный скрипт), собери новые страницы из этих данных и сделай diff текстового содержимого: он обязан быть пустым (кроме двух правок и удалённых CRO-виджетов).
- **Удалить навсегда** (по всему сайту): «Загрузка студии 80% / осталось 2 слота», «Перезвоним за 28 сек», «В работе: N авто», вторые/третьи формы и калькуляторы, дубли прайс-таблиц в DOM, скидочные баннеры с процентами. Их нет ни в одном новом шаблоне.
- **Одна форма на страницу** — квиз из ДС §4.3 + один глобальный sticky CTA. Найди текущий эндпоинт приёма лидов в репо и сохрани интеграцию; квиз шлёт в него.
- **Никакого WebGL и тяжёлых анимационных библиотек.** Моушен — только из списка ДС §5 (CSS + IntersectionObserver). Анатомия — видео+маски, не three.js.
- Бюджеты: LCP ≤ 2.5s, CLS ≤ 0.05, JS страницы услуги ≤ 15 КБ gzip сверх пола фреймворка, SEO 100. Вместо абсолютного perf — сравнительный прогон против боевой страницы (медиана 5 прогонов на одной машине, новая не ниже старой) и компонентные пороги TBT ≤ 300 мс, CLS ≤ 0.05, LCP в реальном браузере ≤ 2.5 с. Пол фреймворка измеряется статической страницей той же сборки: прежний абсолютный порог 150 КБ был ниже пола.

## Порядок работ (жёсткий, с чекпойнтами)

**Фаза 0 — фундамент.** Ветка `redesign`. Подключи токены в tailwind.config, self-host шрифты Unbounded (500/600) + Inter (400–700) через `next/font` с кириллицей, собери базовые компоненты ДС: Button, Header+мегаменю (все 19 услуг), Footer, StickyCTA, ServiceCard, Quiz, PriceTable, BeforeAfter, ReviewCard, ArticleCard. Каждый — со всеми состояниями из ДС. Storybook не нужен — сделай страницу `/dev/ui` со всеми компонентами для визуальной проверки.

**Фаза 1 — эталон `/ppf`.** Собери полностью по `03-template-service.md`, включая миграцию данных, квиз с отправкой лида и оверлей 3D-анатомии в шаге зон. Прогони DoD из §7. **СТОП: покажи /ppf (скриншоты desktop+mobile, diff контента, Lighthouse) и жди подтверждения** — эталон утверждается до тиража.

**Фаза 2 — тираж услуг.** Раскатай шаблон на остальные 18 через данные (никакого копипаста разметки). Особые страницы — по §4 эталонного ТЗ (сохранить интерактивы polirovka/tonirovka, карта лупов).

**Фаза 3 — главная** с анатомией по `03-template-home.md`. **Фаза 4** — портфолио+кейсы (301 для polirovka-work-1…6) и блог со статьями (оглавление, «читайте также»). **Фаза 5** — about/contacts, JSON-LD по schema/README, финальный проход: Lighthouse всех шаблонов, диф всех текстов, проверка 404/редиректов, sitemap.

## Правила работы

- После каждой фазы — короткий отчёт: что сделано, скриншоты, метрики, отклонения от ТЗ (если пришлось) с обоснованием.
- Если ТЗ и текущий код конфликтуют или данных не хватает — не изобретай: задай вопрос списком, предложив вариант по умолчанию.
- Плейсхолдеры, которые остаются до получения данных: `[РЕКВИЗИТЫ]` в футере, `[LAT]/[LON]` в LocalBusiness, `[проверить: N дней]` в кейсах — не заполнять выдуманным.
- Ничего не деплоить без команды; прод не трогать, вся работа в ветке.

Начни с фазы 0: прочитай документацию по списку, осмотри текущий код (структура страниц, источники данных, эндпоинт лидов, счётчик Метрики) и покажи короткий план фундамента с найденными точками интеграции.
